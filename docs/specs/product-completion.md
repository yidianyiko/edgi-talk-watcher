# 看守第一版完成规范

用户授权：完成已列出的六类剩余问题并持续推进，不重复等待一般实现决定；使用保存录像代替真人调试。语音是可选后续能力，优先完成核心六项。当前 board 还不能据已有证据称为独立设备。

## 用户行为与默认选择

1. 输入一句中文，只在新任务建立时编译并持久缓存计划；网页、原始任务 CLI 和计划 CLI 最终使用同一种经过验证的计划。当前支持单目标出现/消失，其他任务明确拒绝。
2. 录像按原始采集时间推进，整段覆盖，使用和实时看守相同的判断状态机。模型响应保留为可重放日志；区分新调用、缓存响应模拟与离线检查。每段模型调用有显式上限，不自动掩盖未覆盖尾部。
3. 事件去重；uncertain 保留短期可信参考，不重置事件锁存；暂停或新任务使旧响应失效。参考时限、超时、调用上限和退出都有可注入时钟的测试。
4. 任务与前后画面事件存本地，刷新和服务重启后可查看；支持清理，默认最多保留100条事件。保存、图片读取和删除必须保持路径约束；错误响应不泄露密钥。
5. 恢复后显示上次任务但默认暂停，避免重启后意外采集。模型错误先暂停且保留重试入口；断网恢复由用户重新开始，不无限自动重试。浏览器后台/设备断开停止新采集并忽略在途结果。
6. 页面及板卡明确显示当前任务、状态、事件计数和操作入口。板端实际能力先探测；采图、联网和触摸/按键控制有真实条件就实现验证，没有则记录具体缺失并继续完成可独立工作的驱动、协议和自测。电脑UART代理不可算独立联网推理。

## 接口约定

- Python engine（slice 001拥有）：`WatchEngine` 接收 validated plan；`observe(frame, judge)` 中 frame含path,time；judge(plan,before,after)返回现有 status/confidence 格式。返回decision并包含 `alert` 布尔值、使用的before/after；`reset`/暂停失效机制由会话边界管理。确切构造参数由001定义后通知002。
- Web（slice 002拥有）：保留 POST /api/judge 兼容边界，生产默认编译任务并缓存，注入judge测试必须显式可控；新增持久任务/事件 API 由002自行定义并统一接入前端。不把编译等待藏在每次23秒图像判断超时内。
- Replay（001拥有）：新增完整录制入口，摄像头和板卡完全不参与；允许明确 --run 模型评估，保存逐轮日志和事件证据；同一份模型响应日志可零联网重跑。
- Firmware（003拥有）：保留原watch_status接口、心跳及M33；扩展任务和用户动作协议，新增板端能力/采集/网络探测命令。在实际可用端口、工具及备份确认前不烧录。
